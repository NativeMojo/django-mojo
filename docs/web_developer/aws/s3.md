# S3 bucket Admin API

The S3 bucket API is a global administrative surface for complete inventory,
private creation, deliberate whole-bucket public/private posture, and
exact-name-confirmed emptying. It never deletes a bucket.

The Admin System Setup UI uses a narrower server-side workflow. It discovers
conservative private media candidates, returns exact names as a required-choice
enum, and adopts the selected bucket as the private system FileManager. The
operation keeps Block Public Access enabled, merges wildcard presigned-upload
CORS without deleting unrelated rules, and is safe to rerun. The UI must not
offer a rejected/public/tenant candidate or invent a name when a suitable
existing media bucket is available.

WebApp release buckets are independent of that system FileManager. Their
readiness check asks for a dedicated CORS rule for the Admin's exact HTTPS
origin and upload headers. An existing wildcard CORS rule can already permit
uploads but does not satisfy that tight-rule audit, so System Setup reports the
dedicated rule as missing; it does not claim the browser is blocked. Apply adds
the portal-specific rule without replacing existing CORS entries.

## Authorization

Every route requires any one global permission:

- `manage_aws`
- `files`

Superusers are accepted. `manage_files`, `view_fileman`, member-only grants,
group-scoped tokens, and API keys are denied. A supplied `group` parameter is
rejected and cannot authorize the operation.

## Routes

| Method | Route | Purpose |
| --- | --- | --- |
| `GET` | `/api/aws/s3/bucket` | Complete account inventory |
| `GET` | `/api/aws/s3/bucket/<name>` | Verified bucket detail |
| `POST` | `/api/aws/s3/bucket/<name>` | Private create or one action |
| `DELETE` | either route | Always `405`; unsupported |

For compatibility, collection GET/POST may receive `bucket_name`. When a path
name exists it is authoritative, and a different request value is `400`.

## Strict POST union

POST accepts only `bucket_name` plus exactly one of these shapes, or no action
key for create:

```json
{}
```

```json
{"set_public": true}
```

```json
{"set_public": false}
```

```json
{"empty": {"confirm_name": "exact-case-sensitive-name"}}
```

`set_public` must be a literal JSON boolean. `empty` must be an object with
exactly the one `confirm_name` key, whose value exactly equals the resolved
bucket. Unknown keys, both actions, additional empty keys, missing names, and
path/body mismatches fail with `400` before AWS client construction.

After validation, empty requires a bearer login whose `auth_time` is no more
than five minutes old. Stale or missing bearer freshness returns the standard
`440 reauth_required` response. Non-bearer authentication retains the
framework's documented fresh-auth bypass, though API keys are already excluded
by the global permission gate.

## Success responses

Inventory is all-or-nothing:

```json
{
  "status": true,
  "code": 200,
  "data": [{"id": "bucket-a", "name": "bucket-a", "created": 1786000000.0}],
  "count": 1,
  "size": 1
}
```

Detail:

```json
{"status": true, "code": 200, "data": {"id": "bucket-a", "name": "bucket-a", "exists": true}}
```

Create is idempotent. `created_new` is `false` for an existing bucket and can
be `null` when a create race/retry proves ownership but not this request's
creation provenance:

```json
{"status": true, "code": 200, "data": {"id": "bucket-a", "name": "bucket-a", "created_new": true}}
```

Access posture:

```json
{
  "status": true,
  "code": 200,
  "data": {
    "name": "bucket-a",
    "is_public": true,
    "configured_public": true,
    "complete": true,
    "mutation_state": "complete"
  }
}
```

`is_public:true` verifies the django-mojo managed anonymous GetObject
statement, bucket PAB, observable account PAB, and AWS policy-status result. It
does not promise an anonymous fetch will succeed through every independent AWS
authorization/encryption layer. Private success verifies all four bucket PAB
flags and deliberately leaves policy text in place. `configured_public` is an
additive compatibility field; consumers should use `is_public`.

Empty returns acknowledged counts only:

```json
{
  "status": true,
  "code": 200,
  "data": {
    "name": "bucket-a",
    "complete": true,
    "mutation_state": "complete",
    "deleted_objects": 4,
    "deleted_versions": 9,
    "deleted_markers": 2,
    "aborted_uploads": 1
  }
}
```

## Failures and recovery

Input errors are `400`. AWS IAM denial is `403`; conclusive missing is `404`;
conflicts/wrong state are `409`; credential/network/throttle/unavailable
families are `503`; other known provider failures are `502`. App permission
denial uses the framework's ordinary 403 envelope and has no provider fields.

Before mutation, a provider failure uses `mutation_state:"none"`. Once work
may have changed AWS state, incomplete responses use HTTP 409 and
`error_code:"s3_operation_incomplete"`:

```json
{
  "status": false,
  "code": 409,
  "error": "S3 bucket empty did not reach a verified empty state",
  "error_code": "s3_operation_incomplete",
  "data": {
    "name": "bucket-a",
    "action": "empty",
    "complete": false,
    "mutation_state": "partial",
    "counts": {
      "deleted_objects": 4,
      "deleted_versions": 3,
      "deleted_markers": 0,
      "aborted_uploads": 1
    },
    "failed": {"objects": 0, "versions": 1, "markers": 0, "uploads": 0},
    "remaining": {"objects": null, "versions": null, "markers": null, "uploads": null},
    "failure": {"operation": "delete_objects", "provider_code": "AccessDenied", "retryable": false}
  }
}
```

States are evidence, not progress percentages:

- `none`: no provider mutation was acknowledged or may have applied;
- `partial`: one or more exact mutations were acknowledged, but final state
  was not verified;
- `unknown`: a mutating transport/provider outcome is ambiguous.

Counts are acknowledgements, never requested totals. `null` remaining counts
mean the action stopped before a safe final probe. Responses never contain
object keys, version ids, upload ids, policy bodies, request ids, or raw AWS
messages.

Public-enable failures also report `requested_public`, `is_public`, additive
`configured_public`, and `safety_lock`. `applied` means the all-private bucket PAB was verified after
failure; `failed` means posture is unknown; `not_needed` means no public
mutation required recovery.

The service has finite time/call/page/batch bounds. `work_limit` is retryable.
Inventory returns no rows when its 10-page/10,000-row cap is exceeded. Empty is
irreversible and non-atomic against active writers; Object Lock, legal hold,
governance retention, MFA Delete, Requester Pays, directory buckets, or
concurrent writes can require manual remediation.

Always refetch inventory/detail after any mutation response, including a
failure. A failed action can have changed external state. Empty is idempotent
and may be retried after stopping writers or correcting IAM/provider posture.
There is no bucket DELETE API.
