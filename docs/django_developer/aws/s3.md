# S3 bucket operations

django-mojo exposes a bounded S3 bucket administration layer through
`mojo.helpers.aws.s3`. It is intended for global administrative inventory,
private bucket creation, whole-bucket public-policy posture, and a confirmed
empty operation. It does not delete buckets.

## Credentials, clients, region, and owner

The helper uses `mojo.helpers.aws.client.get_client()`, so static credentials,
ambient credentials, standard botocore retries, and the shared three-second
connect/read timeouts behave like other AWS helpers. Partial static credential
pairs are rejected. Default AWS S3 clients use regional virtual-host addressing,
so a `us-west-2` presign targets `bucket.s3.us-west-2.amazonaws.com` instead of
the legacy global endpoint. An explicit `endpoint_url` keeps botocore's endpoint
addressing behavior for S3-compatible storage, and a caller-supplied
`botocore.config.Config` remains authoritative.

Bucket detail and mutation first use `HeadBucket` to discover the bucket's
allowlisted region, build one regional client, and repeat the head request.
Only a conclusive provider 404 means missing. Access denial, invalid or absent
region evidence, credentials, throttling, and transport failures are errors.

Access-control and empty operations resolve STS caller identity once, freeze
the 12-digit account id, and pass `ExpectedBucketOwner` to every S3 operation
that supports it. The account id is never returned or logged. S3 Control uses
the same credential and region context for account-level Public Access Block.

## Structured results and errors

The REST-facing methods are:

```python
bucket = S3Bucket("example-bucket")
bucket.create_private()
bucket.set_public(True)   # or False
bucket.empty()
```

Success dictionaries are explicit and bounded. Mutation success always has
`complete: true` and `mutation_state: "complete"`, except create, whose
`created_new` may be `true`, `false`, or `null` when retry provenance is
unknowable.

`S3OperationError` contains only an operation name, allowlisted provider code,
HTTP status, retryability, mutation state, safe aggregate data, and a fixed
message. Its string and representation do not contain the source exception.
The original exception is available only through Python exception chaining.

Mutation states mean:

- `none`: no mutation was acknowledged or may have been applied;
- `partial`: at least one exact mutation was acknowledged but the requested
  final state was not verified;
- `unknown`: a mutating call had an ambiguous transport/provider outcome.

Unknown provider codes collapse to `provider_error`. Raw provider messages,
request ids, policy documents, object keys, version ids, and upload ids are
never result or log fields.

## Bounded work

One logical bucket operation has a monotonic 25-second budget, 200 provider
calls, 20 object/version/upload list pages, 50 delete batches, and 250 upload
abort attempts. Each multipart upload is retried at most three times. Work
exhaustion is retryable `work_limit`; an operator can correct the blocker and
repeat the idempotent action.

Account inventory has a separate all-or-nothing bound: the `ListBuckets`
paginator uses 1,000-row pages and returns at most 10 pages/10,000 rows. If
continuation remains, the entire read fails. A partial inventory is never
returned as a complete account view.

## Private creation

`create_private()` is idempotent. An existing bucket returns
`created_new:false` and is not changed. A new bucket is created in the selected
region, receives all four bucket Public Access Block flags set to true, and is
read back for exact verification. `us-east-1` omits
`CreateBucketConfiguration` as required by S3.

An acknowledged create followed by a PAB failure is a partial result. The
helper never rolls back by deleting the bucket. A create race owned by this
account can return `created_new:null`; a globally occupied name is a conflict.
Bucket creation does not install CORS. FileManager remains responsible for its
own CORS configuration.

## System Setup media-bucket adoption

Admin System Setup uses the narrower converger in
`mojo.apps.aws.services.aws_setup`, not the general bucket API. Its read-only
discovery returns complete exact bucket names and rejects candidates in another
region, website buckets, buckets with a public policy, tenant/user-tagged
buckets, and buckets whose posture cannot be classified safely. It never
invents a random name when an existing private media bucket is available.

Adoption requires the exact candidate plus affirmative consent. Under the
frozen installation identity, the converger refuses cross-installation
ownership, enables all four Block Public Access controls, merges ownership tags
and wildcard presigned-upload CORS without replacing unrelated entries, then
creates or repairs the private system-default FileManager with direct uploads
and `allowed_origins=["*"]`. It verifies CORS after writing and retries once
around a concurrent CORS writer.

No public bucket policy is created or rewritten. CORS grants no S3 permission;
the browser still needs a presigned operation authorized by Django. Reruns are
idempotent and preserve buckets, objects, policies, and unrelated CORS rules.

The legacy `create(region=..., public_access=...)` boolean signature remains
available for SES and external Python compatibility. `public_access=True`
retains its historical meaning of skipping the private-PAB setup; it does not
install the verified public policy.

## Whole-bucket public and private posture

Public mode keeps ACL creation and evaluation blocked while disabling only the
two policy-specific PAB flags. It owns one exact policy statement:

```text
Sid: DjangoMojoBucketPublicRead
Effect: Allow
Principal: *
Action: s3:GetObject
Resource: arn:aws:s3:::<bucket>/*
```

Before mutation it reads bucket PAB, bucket policy, account PAB, and policy
status. Account `BlockPublicPolicy` or `RestrictPublicBuckets` refuses the
request without mutation. The policy is re-read immediately before the write.
An exact managed statement is reused; the same Sid with different semantics is
a conflict. Every unrelated top-level property and statement is retained.

After mutation, the helper verifies bucket PAB, the exact statement, semantic
equality of unrelated policy content, account PAB, and
`GetBucketPolicyStatus.IsPublic`. S3 policy writes have no conditional token,
so strict serialization is impossible; use a single policy writer when that
guarantee is required. A detected concurrent semantic change is incomplete.

If public enablement fails after a mutation, the helper immediately applies
and verifies all-four-true bucket PAB. It reports `safety_lock: "applied"` only
when verified; otherwise public posture and mutation state are unknown. It
does not restore a stale policy snapshot.

Private mode only applies and verifies all-four-true bucket PAB. It leaves all
policy statements intact. `is_public` is the consumer-facing verified
observable policy/PAB posture, not anonymous fetch success or every SCP,
access-point, ownership, encryption, or object-level authorization layer.
`configured_public` is retained as additive compatibility detail.

## Confirmed empty algorithm

The REST layer owns exact-name confirmation and five-minute fresh auth. The
helper then performs this bounded provider transition:

1. Region-correct, owner-bound `HeadBucket`, versioning, one-row object/version,
   and multipart-upload probes complete before the first mutation.
2. Outstanding multipart uploads are aborted first. Each acknowledged abort
   is checked with `ListParts`; `NoSuchUpload` or an empty parts response proves
   terminal state without inventing an acknowledgement.
3. Versioning is re-read. Versions, null versions, and delete markers are
   repeatedly listed from the first page and permanently deleted with their
   exact `VersionId`.
4. Key-only deletion runs only while fresh versioning reads prove the bucket
   has never been versioned. It is never used for Enabled or Suspended buckets,
   where it would create another delete marker.
5. Versioning is reconciled and independent one-row object, version/marker,
   and upload probes must all be empty.

`DeleteObjects` uses batches of at most 1,000 and `Quiet:false`. Counts increase
only for exact entries in `Deleted`. Per-item `Errors` and identifiers absent
from both response arrays stop the action. Pagination markers are paired, and
mutating sweeps restart at the first page because old continuation state is
stale after mutation.

Active writers can race the operation. Residual final-probe state makes the
request incomplete; empty does not claim transaction isolation. Object Lock,
legal hold, governance retention, MFA Delete, Requester Pays, directory/S3
Express buckets, and unsupported owner/policy postures require manual operator
remediation. The helper never attempts a bypass.

## IAM actions

Grant only the actions needed by enabled operations. Resource scoping varies by
AWS API: account inventory, STS identity, and account PAB cannot be constrained
to one bucket ARN in the same way as object/bucket operations.

| Operation | IAM actions |
| --- | --- |
| Inventory/detail | `s3:ListAllMyBuckets`, `s3:ListBucket` |
| Create/private lock | `s3:CreateBucket`, `s3:GetBucketPublicAccessBlock`, `s3:PutBucketPublicAccessBlock` |
| Owner/account posture | `sts:GetCallerIdentity`, `s3:GetAccountPublicAccessBlock` |
| Public policy | `s3:GetBucketPolicy`, `s3:PutBucketPolicy`, `s3:GetBucketPolicyStatus`, bucket PAB actions above |
| Empty inventory | `s3:GetBucketVersioning`, `s3:ListBucket`, `s3:ListBucketVersions`, `s3:ListBucketMultipartUploads`, `s3:ListMultipartUploadParts` |
| Empty mutation | `s3:AbortMultipartUpload`, `s3:DeleteObject`, `s3:DeleteObjectVersion` |

There is no REST bucket-delete operation. The older Python `delete()` and
`delete_all_objects()` compatibility helpers are not used by this Admin
contract and do not receive its confirmation, completeness, or version-aware
guarantees.
