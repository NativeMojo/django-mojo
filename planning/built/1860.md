### UX Coherence Amendment

- **One ownership chain:** Dashboard answers health and links to the exact remedy; System Setup owns installation repair; Settings owns configuration discovery; Platform owns operational evidence; Domains & DNS owns records; Web Apps owns onboarding; Advanced owns expert diagnostics only.
- **Exact deep links:** add route-state focus/return support. Public API configuration links to #/setup focused on django.base_url; fleet links to Platform focused on Fleet; incidents/tickets link to the exact Activity tab. Never send an actionable Dashboard card to generic Open Platform.
- **Simplify Platform:** remove the duplicate Domains card and the expanded eight-link Advanced directory. Evidence cards may expose one contextual owner action. Advanced is summary-first inventory/diagnostics with raw JSON collapsed and no protected-settings claim.
- **Simplify Setup:** above the fold show readiness summary, issue count, and one primary Fix all action. Remove the duplicate Network & Hosting directory/checklist from the repair flow; post-success next steps may be compact links.
- **Truthful repair rows:** each failed check has at most one action: Configure, Open owner, or Change deployment setting. Only django.base_url starts its durable fix. Hide check codes and operation logs under closed Technical details.
- **Professional operation lifecycle:** fullscreen busy is active only while the server advances. Close it for a required choice and focus the inline choice. Show real step/progress, prevent duplicate mutations, then leave terminal success/failure and refreshed evidence visible. Success offers Return to Dashboard and Onboard WebApp.
- **440 behavior:** preflight recent authentication before beginning a mutation where possible. Preserve idempotent intent only when it can be safely reconciled; otherwise return with explicit Identity confirmed—select Fix all again. Never silently drop or replay a mutation.
- **Status language:** reserve red/unhealthy for current proven failure. Missing required configuration is Needs setup; optional configuration is warning; historical onboarding never establishes current health.
