# Maestro item 2860 — Explicit live runner IDs are rejected as box-direct channels

- Source: https://maestromojo.com/app/#/board/11?item=2860
- Build started: 2026-08-24

A jobs engine may start with a safe explicit runner ID that enforced publishing later refuses, even though the engine advertises that exact ID as a consumed direct channel. Enforced immediate publishing should accept a nonsuffix runner ID only while its exact heartbeat is current and self-consistent; unknown, stale, malformed, mismatched, or opted-out names must still fail closed.

## Acceptance

- `parse_runner_id_arg()` continues accepting all existing safe runner IDs; no `-engine` suffix becomes mandatory.
- Enforced immediate publishing accepts an otherwise undeclared ID only from an exact, current, positive-TTL heartbeat that identifies the same runner and advertises the same direct channel.
- Missing, expired, persistent, malformed, mismatched, stale, future-skewed, Redis-unreadable, or opted-out heartbeat data fails closed.
- Existing default, local, declared, and `-engine` rules remain unchanged and bypass the dynamic lookup.
- The lookup is one bounded, primary-only, nontransactional exact GET+TTL pipeline; no scan or roster.
- `ScheduledTask.channel` retains static declaration semantics.
- Add a failing regression first and update both developer documentation tracks.
- Commit `286f94f6` remains the sole legacy deploy-shim elevation fix.
